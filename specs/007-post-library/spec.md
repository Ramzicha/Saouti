# Feature Specification: 007 — Post Library

**Feature Branch**: `007-post-library`  
**Created**: 2026-10-23  
**Status**: Ready  
**Input**: User description: "Add the post library to Saouti. Every generated post is saved automatically with its edits and can be copied in one click exactly as it should be pasted, preserving line breaks, emoji and hashtags. Users browse their posts with combined filters (platform, status of draft, ready or posted, date range, tag), search post text in any language including Arabic, mark posts as posted with an optional link and date, view and restore earlier versions, and delete posts with a ten-second undo. Lower priority: export of selected posts or the whole library as text or Markdown. Out of scope: scheduling, publishing, analytics, sharing posts with other users. Clarify — focus areas: how many versions to keep; whether deleted posts can be recovered after the undo window; tag creation and limits; pagination size."

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Auto-Save, One-Click Copy & Post Editing (Priority: P1) 🎯 MVP

As a content creator or professional using Saouti,  
I want every post generated by the agent engine to be saved automatically to my library,  
So that I never lose generated drafts, can edit them with live saving, and can copy them to my clipboard in one click with exact formatting, line breaks, emojis, and hashtags ready for pasting.

**Why this priority**: Without automatic persistence and reliable one-click copying, generated posts are transient and risk being lost upon navigation or reload. This forms the absolute core MVP of the Post Library.

**Independent Test**: Trigger a post generation run; navigate to `/library` (or Drafts); verify all platform versions appear with status "draft" or "ready"; edit post copy; verify changes are saved; click "Copy"; paste into an external text editor and verify exact preservation of line breaks, emoji characters, and hashtags.

**Acceptance Scenarios**:
1. **Given** a multi-agent generation run completes in the workspace, **When** the user opens the post library, **Then** all generated platform posts are automatically listed as saved items with their associated platform, language, image prompt, and timestamps.
2. **Given** a post in the library, **When** the user clicks the "Copy" action, **Then** the exact text content (including blank line breaks, Unicode emojis, and hashtag blocks) is copied to the system clipboard, and a temporary confirmation badge ("Copied!") appears for 2 seconds.
3. **Given** a post in the library, **When** the user edits the content or image prompt and saves, **Then** the updated text is immediately persisted and a new version snapshot is recorded.

**Test Plan**:
- Unit: Validation of text formatting serializer, clipboard payload formatter, and post schema constraints.
- Integration: Verification of auto-saving post records upon pipeline completion and manual post editing with version creation.
- Security path covered: [x] Yes (tenant isolation ensuring users can only read and mutate their own posts).

### User Story 2 - Combined Filtering, Tagging & Multilingual Arabic Search (Priority: P1)

As a multilingual professional,  
I want to browse my library using combined filters (platform, status, date range, tags) and search post text in Arabic, French, and English,  
So that I can locate specific talking points, campaigns, or platform variants effortlessly.

**Why this priority**: As the library grows, finding and organizing posts across platforms, publishing statuses, and multiple languages is essential for daily content reuse.

**Independent Test**: Create 10 posts across LinkedIn, X, and Reddit with statuses `draft`, `ready`, and `posted`, tagging some with "AI" and "Architecture"; apply filter `platform=LinkedIn` AND `status=ready` AND `tag=AI`; verify only matching posts appear. Execute Arabic text search with diacritics and Alef variants (e.g., `أزمة` vs `ازمة`); verify accurate query matching.

**Acceptance Scenarios**:
1. **Given** a library containing posts across multiple platforms, **When** the user selects filters (e.g. Platform: LinkedIn + Status: Ready + Date Range: Last 30 Days), **Then** only posts satisfying all active filter criteria are displayed.
2. **Given** posts written in Arabic, **When** the user searches for a term using alternative character forms (e.g. Alef with/without Hamza, Taa Marbuta vs Haa), **Then** the search matches relevant Arabic posts regardless of orthographic variations.
3. **Given** a post card, **When** the user adds or removes tags, **Then** the tags update immediately and are indexed for future filtering. Users can create freeform tags up to a maximum of 5 tags per post, with each tag capped at 30 characters.

**Test Plan**:
- Unit: Arabic text normalization and query matching tests; filter combination logic unit tests.
- Integration: Multi-condition database querying and tag indexing tests.
- Security path covered: [x] Yes (SQL injection and search query sanitization).

### User Story 3 - Version History & Restoration (Priority: P2)

As a creator iterating on my thoughts,  
I want to inspect earlier versions of a post and restore a previous version if needed,  
So that I can experiment freely with edits without worrying about losing past phrasing.

**Why this priority**: Creators refine hooks, tone, and formatting over time; having an accessible audit history provides psychological safety and rapid reversion.

**Independent Test**: Edit a post three times; open its version history drawer; verify all three version timestamps, word counts, and diffs are viewable; select Version 1 and click "Restore"; verify the post content reverts to Version 1 while creating a new active version entry.

**Acceptance Scenarios**:
1. **Given** a post with multiple edits, **When** the user opens the "Version History" view, **Then** the system displays up to the 20 most recent versions listed chronologically with edit timestamps and character counts, automatically pruning older versions when subsequent edits occur.
2. **Given** an earlier version in the history list, **When** the user clicks "Restore this version", **Then** the current post content updates to match the selected historical version and an audit entry is created.

**Test Plan**:
- Unit: Version diffing helper, version retention pruning logic.
- Integration: Version creation on edit and rollback execution.
- Security path covered: [ ] N/A

### User Story 4 - Status Tracking & Deletion with 10-Second Undo (Priority: P2)

As a user managing content lifecycle,  
I want to mark posts as "posted" with an optional URL and date, and delete posts with a 10-second undo window,  
So that I maintain an accurate record of published work and can safely delete unwanted posts without fear of accidental clicks.

**Why this priority**: Tracking which posts have been published prevents duplicate posting, and a 10-second undo prevents accidental data loss during library cleanup.

**Independent Test**: Mark a "ready" post as "posted", entering a link `https://linkedin.com/posts/123` and date; verify status badge updates to "posted" and displays the link. Click "Delete"; verify the post disappears from the active view while a floating toast with a 10-second live countdown timer appears; click "Undo" within 10 seconds and verify the post is fully restored. Allow countdown to reach zero and verify post deletion permanence.

**Acceptance Scenarios**:
1. **Given** a post with status `ready` or `draft`, **When** the user marks it as `posted`, **Then** the user can optionally input a published URL and publication date, and the post status updates to `posted`.
2. **Given** any post, **When** the user clicks "Delete", **Then** the post is immediately hidden from the active list, and a floating toast displays "Post deleted" with a 10-second countdown bar and an "Undo" button.
3. **Given** the undo toast is visible, **When** the user clicks "Undo" before 10 seconds elapse, **Then** the deletion is cancelled and the post reappears in its original position.
4. **Given** the 10-second undo timer expires without user interaction, **When** the window closes, **Then** the post is moved to a 30-day Trash bin where the user can view, restore, or permanently purge it before automated expiration after 30 days.

**Test Plan**:
- Unit: Countdown timer hook, deletion state transition logic.
- Integration: Mark as posted with metadata; undo cancellation vs expiration.
- Security path covered: [x] Yes (safe cascading deletion without orphaned records).

## Edge Cases

- **Special Characters & Emojis in Clipboard**: Multi-byte emojis, skin tone modifiers, RTL markers, and consecutive newlines must not be stripped or corrupted by the clipboard API.
- **Arabic Text Normalization**: Search queries with or without Tashkeel (harakat), Tanween, Tatweel (kashida), or different Alef forms (`أ`, `إ`, `آ`, `ا`) must match accurately.
- **Large Library Pagination**: When a user accumulates hundreds of posts, the library must load incrementally (page size default: 20 items) without degraded UI responsiveness or heavy payloads.
- **Rapid Deletion & Multiple Undo Toasts**: If a user deletes multiple posts in quick succession, each toast/action must remain distinct or queue properly without race conditions.
- **Published Link Validation**: When marking as posted, the link input must validate URL structure (must be `https://` if provided, or allow leaving blank).
- **Concurrent Edits Across Tabs**: If a user has the same post open in two browser tabs, conflicting edits must increment version numbers safely.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST automatically create a new post record in the library for every platform draft output produced by a generation run.
- **FR-002**: System MUST provide a one-click copy action that copies post text to the system clipboard preserving exact line breaks, emojis, and hashtags without adding unwanted formatting.
- **FR-003**: System MUST provide a post editor allowing users to modify post text, hashtags, and image prompt with auto-save or explicit save.
- **FR-004**: System MUST maintain version history for each post, retaining up to the 20 most recent versions and capturing a timestamped snapshot whenever content is updated.
- **FR-005**: System MUST allow users to view earlier post versions and restore any selected version as the active version.
- **FR-006**: System MUST support combined multi-attribute filtering: by platform (`linkedin`, `x`, `reddit`, `instagram`, `facebook`), by status (`draft`, `ready`, `posted`), by date range (created/updated), and by tags.
- **FR-007**: System MUST provide full-text search across post text and hashtags supporting English, French, and Arabic (with normalization for Alef forms, Taa Marbuta, and diacritics).
- **FR-008**: System MUST allow users to assign and remove freeform tags on posts, with a limit of up to 5 tags per post and a maximum length of 30 characters per tag.
- **FR-009**: System MUST allow users to transition post status between `draft`, `ready`, and `posted`, capturing an optional published URL and publication date when marked as `posted`.
- **FR-010**: System MUST support post deletion with an immediate 10-second floating countdown undo banner; if not undone within 10 seconds, the post MUST move to a 30-day Trash bin where users can recover or permanently delete it.
- **FR-011**: System MUST paginate or virtualize library lists with a default page size of 20 posts per page.
- **FR-012**: System MUST allow exporting selected posts or all filtered posts to structured Markdown (`.md`) or plain text (`.txt`).
- **FR-013**: System MUST enforce strict tenant data isolation, ensuring users can only read, update, or delete their own posts, versions, and tags.

---

### Key Entities

- **Post**: Represents a single platform content asset in the library. Key attributes: `id`, `userId`, `runId` (optional link to originating run), `platform`, `language`, `status` (`draft` | `ready` | `posted`), `content`, `hashtags`, `imagePrompt`, `imageAltText`, `imageAspectRatio`, `publishedUrl`, `publishedAt`, `deletedAt` (nullable timestamp for 30-day trash retention), `createdAt`, `updatedAt`.
- **PostVersion**: Historical immutable snapshot of a post before an update (capped at 20 most recent). Key attributes: `id`, `postId`, `versionNumber`, `content`, `hashtags`, `imagePrompt`, `createdAt`.
- **Tag**: Categorization label applied to posts. Key attributes: `id`, `userId`, `name` (max 30 characters), `color`.
- **PostTag**: Association between posts and tags (max 5 per post).

## Accessibility & Localisation *(mandatory — Principle 6)*

- **A11Y-001**: All buttons, copy triggers, filter dropdowns, search inputs, and undo banners MUST be fully keyboard-navigable with visible focus indicators.
- **A11Y-002**: Colour contrast in light and dark themes MUST meet WCAG 2.1 AA (≥ 4.5:1 for normal text, ≥ 3:1 for badges and chips).
- **A11Y-003**: The 10-second undo countdown MUST provide an accessible text equivalent (e.g. `aria-live="polite"` announcing "Post deleted. Press Undo to restore within 10 seconds").
- **A11Y-004**: Automated axe-core checks MUST pass for library views, post detail modals, and filter panels.
- **I18N-001**: All user-facing strings (empty states, filter labels, status chips, copy confirmations, export prompts, undo notices) MUST be externalised in `messages/en.json`, `messages/fr.json`, and `messages/ar.json`.
- **I18N-002**: Full RTL layout MUST be verified for Arabic, with reverse filter row alignment, search input directionality, and proper placement of copy buttons and action menus.
- **I18N-003**: Search normalization MUST natively handle Arabic character variants without requiring exact diacritical matching from the user.

---

## Assumptions

- **Pagination Size**: Default page size is set to 20 posts per page to balance network payload and smooth scrolling.
- **Out of Scope**: Direct publishing/API scheduling, engagement analytics, multi-user workspace collaboration, and social platform OAuth publishing remain strictly out of scope.
- **Originating Runs**: Posts created by runs link back to their originating `runId`, but manually created or duplicate posts can also exist without a `runId`.

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of posts completed by the generation pipeline are automatically saved to the library without requiring manual user intervention.
- **SC-002**: One-click copying executes and confirms to the user in under 150 milliseconds, with zero loss of emojis, line breaks, or hashtags when pasted.
- **SC-003**: Filter and search queries return matching posts in under 200 milliseconds for libraries containing up to 1,000 posts.
- **SC-004**: Users can undo accidental deletion within the 10-second window with 100% data recovery of the post and all its previous versions.
- **SC-005**: Arabic text searches successfully match target posts regardless of whether users include or omit common diacritics and Alef variations.
