# Feature Specification: Post Images & Visual Generation

**Feature Branch**: `008-post-images`  
**Created**: 2026-10-23  
**Status**: Draft  
**Input**: User description: "Add images to Saouti posts. Each post shows an editable, copyable image prompt, aspect ratio and alt text written by the Art Director. Where the user's own provider key supports image generation, the user can generate the image inside Saouti; if it does not, the interface says so plainly and the prompt remains the result. Generated images are stored privately, attached to the post, downloadable, and deleted with the post. Progress and errors are shown as Art Director states. Lower priority: regenerating an image with an instruction while keeping earlier images. Out of scope: image editing tools, branded templates, carousels, video. Clarify — focus areas: which image models and sizes are supported per platform; maximum file size and retention; what the user sees when image generation is rate limited."

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Editable & Copyable Image Prompts (Priority: P1)

As a professional using Saouti, I want each generated post to provide an image prompt, recommended aspect ratio, and accessibility alt text crafted by the Art Director agent, so that I can readily inspect, customize, and copy the visual brief to any external tool or prepare it for generation.

**Why this priority**:
Every post generated by Saouti must have complete visual guidance regardless of whether the user possesses an image-capable AI key. The image prompt, ratio, and alt text provide standalone creative value and guarantee graceful zero-cost utility.

**Independent Test**:
Can be tested independently by generating or viewing any post in the workspace or library, observing the Art Director visual section (prompt, ratio badge, alt text), editing the prompt text in-place, and clicking "Copy Prompt" to verify clipboard output.

**Acceptance Scenarios**:
1. **Given** a post generated by the multi-agent engine, **When** the user views the post card or post detail modal, **Then** the card displays the Art Director image prompt, recommended aspect ratio (e.g., 16:9, 1:1, 4:5), and accessibility alt text.
2. **Given** an existing post with an Art Director prompt, **When** the user edits the image prompt or alt text and saves, **Then** the modifications are saved and reflected in the post library.
3. **Given** an image prompt on a post card, **When** the user clicks "Copy Prompt", **Then** the exact image prompt text is copied to the clipboard, and an accessible confirmation feedback indicator appears for 2 seconds.

**Test Plan** *(Principle 3 — required)*:
- Unit: Validation of prompt and alt-text schema inputs; clipboard formatter tests for image prompts.
- Integration: API post update endpoint tests verifying persistence of edited `imagePrompt`, `aspectRatio`, and `altText`.
- Security path covered: [x] Yes / [ ] N/A *(HTML escaping & prompt injection boundary isolation on edited prompts)*.

### User Story 2 - Image Generation with BYOK & Graceful Degradation (Priority: P1)

As a professional with a configured AI provider key, I want to trigger image generation directly inside Saouti, so that my post is visually accompanied without leaving the platform. If my key tier does not support image generation, I want a plain, polite explanation without breaking my workflow.

**Why this priority**:
Direct generation fulfills the visual promise of the platform for users with enabled keys, while transparent capability detection prevents confusion and failed requests for standard text-only free tier keys.

**Independent Test**:
Can be tested by clicking "Generate Image" on a post with an enabled provider key to verify that image generation runs and produces a preview. Can also be tested with a text-only or unsupported key to verify that the UI shows a clear, non-blocking explanation leaving the prompt intact.

**Acceptance Scenarios**:
1. **Given** an authenticated user whose configured provider key supports image generation, **When** the user clicks "Generate Image" on a post, **Then** an image generation request is initiated, and live Art Director agent states are displayed (e.g., "Art Director · Composing visual asset...").
2. **Given** a user whose provider key lacks image generation capability or model access, **When** the user attempts to generate an image or opens the visual panel, **Then** the UI clearly displays: *"Your configured AI provider key does not support direct image generation. You can copy the Art Director prompt above and generate the image using your preferred visual tool."* and leaves the prompt editable.
3. **Given** an active image generation request, **When** the provider experiences a rate limit (HTTP 429) or transient delay, **Then** the Art Director state displays a transparent status: *"Art Director · Paused, quota reached, retrying in [X] s"* and automatically retries with exponential backoff or allows manual cancellation.

**Test Plan** *(Principle 3 — required)*:
- Unit: Provider capability check tests; rate-limit error normalization tests for image generation requests.
- Integration: Provider adapter image generation integration tests against fake adapter and real key contract.
- Security path covered: [x] Yes / [ ] N/A *(API key encryption preserved; user quota usage counters updated without exposing credentials)*.

### User Story 3 - Secure Storage, Attachment & One-Click Download (Priority: P1)

As a professional, I want generated images securely attached to my post, accessible only to me, and downloadable in high quality with one click, so that I can publish them to my social platforms. When I delete a post, all attached images must be permanently removed.

**Why this priority**:
Privacy and clean data lifecycle management are mandatory under Principle 2 (Security and Privacy First). Users must own their assets, keep them confidential, and experience zero orphan storage leaks upon deletion.

**Independent Test**:
Can be tested by generating an image, verifying it renders on the post card, clicking "Download Image" to verify the downloaded file has the correct MIME type and dimensions, and deleting the parent post to verify the image file and records are completely deleted.

**Acceptance Scenarios**:
1. **Given** a successfully generated image, **When** generation completes, **Then** the image is privately saved in application storage, linked to the post, and displayed in the post card preview with proper alt text.
2. **Given** a post with an attached generated image, **When** the user clicks "Download Image", **Then** the image file is downloaded to their local device with a clean filename formatted as `saouti-[platform]-[post-id].[ext]`.
3. **Given** an image attached to a post, **When** an unauthorized or unauthenticated user attempts to access the image URL directly, **Then** access is denied with a 403 Forbidden or 404 Not Found response.
4. **Given** a post with attached images, **When** the post is permanently deleted or purged from trash, **Then** all linked image records and underlying binary storage files are permanently deleted.

**Test Plan** *(Principle 3 — required)*:
- Unit: Image file attachment validation and mime-type verification.
- Integration: Auth-gated image serving endpoint tests verifying cross-user isolation; cascade deletion tests verifying storage file removal on post deletion.
- Security path covered: [x] Yes / [ ] N/A *(Principle 2: Cross-user authorization check on image endpoints; directory traversal prevention on image paths)*.

### User Story 4 - Image Regeneration with Custom Instructions (Priority: P2)

As a professional, I want to regenerate an image by giving the Art Director an additional refining instruction while keeping my previous generated images, so that I can iterate toward the best visual without losing earlier versions.

**Why this priority**:
Creative direction is iterative. Being able to refine a prompt (e.g., "make the lighting warmer", "add more minimalism") without overwriting previous successful attempts allows users to pick their preferred image.

**Independent Test**:
Can be tested by entering a refinement instruction on an existing post image, clicking "Regenerate", verifying a new image is generated, and switching between the version thumbnails on the post card to select the active image.

**Acceptance Scenarios**:
1. **Given** a post with an existing generated image, **When** the user enters a refinement instruction (e.g., *"Make the background clean and minimalist"*) and clicks "Regenerate", **Then** the Art Director agent generates a new image based on the instruction and attaches it to the post.
2. **Given** multiple generated images for a single post, **When** viewing the post visual gallery, **Then** the user can view thumbnails of all iterations, see the instruction used for each, select which image is primary, or delete specific unwanted variants.

**Test Plan** *(Principle 3 — required)*:
- Unit: Regeneration instruction validation and prompt composition.
- Integration: Multi-image version association per post; active image selection endpoint.
- Security path covered: [x] Yes / [ ] N/A *(Refinement input sanitized and tagged as user data)*.

### Edge Cases

- **Key without Imagen/Image capability**: If the user's Gemini key does not have Vertex/Imagen permissions or is a standard free-tier key that rejects image calls with 404/403, the UI immediately flags the capability status and disables the generation button with an informational tooltip.
- **Provider Quota Exceeded during generation**: If a 429 quota error occurs midway through generation, the Art Director banner indicates the quota pause and retry countdown, allowing the user to either wait or cancel without hanging.
- **Image generation timeout or disconnect**: If the network connection drops or provider takes longer than 60 seconds, the job is marked failed with a descriptive message and a "Retry" button.
- **Large storage bounds**: Uploaded or generated images exceeding 10 MB are rejected with a clear size warning.
- **Post rollback or restore**: When a post version is restored in the library, the active image reference is maintained consistently.
- **Content filtering / Safety block**: If the image provider blocks a prompt due to safety policy, the Art Director displays a polite explanation: *"The provider was unable to generate an image for this prompt due to safety policies. You can edit the prompt and try again."*

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Every generated post MUST include Art Director visual metadata: an editable `imagePrompt`, a recommended `aspectRatio` (16:9, 1:1, or 4:5), and descriptive `altText`.
- **FR-002**: Users MUST be able to edit and copy the image prompt, aspect ratio, and alt text from both the post generation card and the post library.
- **FR-003**: The system MUST detect whether the user's configured AI provider adapter supports image generation via `generateImage`.
- **FR-004**: If the configured key does not support image generation, the system MUST show a plain explanation banner and maintain the editable prompt as the complete visual output.
- **FR-005**: When image generation is triggered, the system MUST display live Art Director agent activity states (e.g., "Art Director · Composing visual asset...", "Art Director · Generating image...").
- **FR-006**: Generated images MUST be stored in private, protected storage accessible only to the authenticated post owner.
- **FR-007**: Generated images MUST be downloadable via an authenticated endpoint with proper content-disposition and filenames.
- **FR-008**: When a post is permanently deleted, all attached image records and stored files MUST be permanently deleted (cascading cleanup).
- **FR-009**: The default image generation model MUST be `imagen-3.0-generate-002` (configurable via runtime settings), with Art Director aspect ratio presets: LinkedIn (16:9), Instagram (1:1 or 4:5), X (16:9), Facebook (16:9), and Reddit (16:9).
- **FR-010**: Image storage MUST enforce a maximum file size of 10 MB per image and retain up to 5 image versions/iterations per post, automatically pruning the oldest non-primary iteration when exceeded.
- **FR-011**: When image generation encounters provider rate limits (HTTP 429), the system MUST display a transparent Art Director state with a live countdown ("Art Director · Paused, quota reached, retrying in [X] s") and retry up to 2 times with exponential backoff, while providing a manual "Cancel" button.
- **FR-012**: Users MUST be able to regenerate an image with custom refinement instructions while retaining earlier visual versions on the post.
- **FR-013**: The UI MUST allow selecting which generated image is the active/primary image for a post.
- **FR-014**: All image prompts and refinement instructions MUST be treated as data inside tagged blocks (`<image_brief>`, `<instruction>`) to prevent prompt injection.

### Key Entities

- **PostImage**: Represents a generated or attached image asset.
  - Attributes: `id`, `postId`, `userId`, `storagePath`, `mimeType`, `fileSizeBytes`, `width`, `height`, `aspectRatio`, `prompt`, `altText`, `instruction`, `versionNumber`, `isPrimary`, `createdAt`.
- **Post (extended)**:
  - Attributes: `hasImage` (boolean flag for quick library filtering), active image reference.
- **ImageGenerationJob / State**:
  - Attributes: `jobId`, `postId`, `status` (`pending`, `generating`, `rate_limited`, `completed`, `failed`), `retryCount`, `errorReason`.

## Accessibility & Localisation *(mandatory — Principle 6)*

- **A11Y-001**: All image interaction controls (generate, edit, copy prompt, download, regenerate) MUST be fully keyboard-navigable and have visible focus indicators.
- **A11Y-002**: Generated image previews MUST include the Art Director generated `alt` attribute for screen readers.
- **A11Y-003**: Colour contrast for all buttons, badges, and status banners MUST meet WCAG 2.1 AA (≥ 4.5:1).
- **A11Y-004**: Loading animations, progress indicators, and countdown bars MUST respect `prefers-reduced-motion`.
- **I18N-001**: All user-facing strings (labels, tooltips, capability banners, status lines, error messages) MUST be externalised in locale files for English (`en`), French (`fr`), and Arabic (`ar`).
- **I18N-002**: The image controls layout, preview gallery, and version thumbnails MUST fully support RTL directionality in Arabic.
- **I18N-003**: Art Director generated alt text and suggested prompts MUST match the post's content language.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of posts generated by the engine contain an image prompt, aspect ratio, and accessibility alt text.
- **SC-002**: Users can copy an image prompt or download a generated image in 1 single click.
- **SC-003**: When image generation is triggered with an enabled key, visual generation starts in under 2 seconds and displays transparent Art Director states.
- **SC-004**: Zero cross-user data leakage: 100% of image asset retrieval requests are authenticated and authorized strictly to the post owner.
- **SC-005**: 100% of orphaned storage files are cleaned up upon permanent post deletion.

---

## Assumptions & Boundaries

### Assumptions
- **Provider Models**: Gemini Imagen 3 (`imagen-3.0-generate-002`) or compatible image generation endpoints when available on the user's API key.
- **Platform Aspect Ratios**: LinkedIn (16:9), Instagram (1:1 or 4:5), X (16:9), Facebook (16:9 or 1:1).
- **Storage Strategy**: Local encrypted filesystem storage in production/container with authenticated streaming route, abstractable to S3/object store if needed later.

### Out of Scope
- In-browser image editing tools (cropping, rotation, canvas drawing, filters).
- Branded templates (quote cards, text-on-image canvas generators, carousels).
- Video generation or animation.
- Automatic posting of images directly to social media networks via third-party APIs.
